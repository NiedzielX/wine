## Testy: wykluczenia z pokrycia i miejsce testów

Przeniesione z `AGENTS.md` §7 bez zmiany treści.

- **Wykluczenia z raportu pokrycia są jawne, w konfiguracji każdego pakietu** (`vitest.config.ts`), z uzasadnieniem: pliki stron i komponentów React (`app/src/app/**.tsx`, pokrywa je E2E), kod shadcn/ui, pakiet `mockups` (prototyp do wycofania), wspólne zestawy testów (`core/src/testing`), repozytoria i encje (pokrywa je `test:db`). Nowe wykluczenie wymaga zgody właściciela.
- **Gdzie piszemy testy:** `core/tests/` (logika domeny), `db/tests/` (bez bazy: `*.test.ts`; z bazą: `*.integration.test.ts`), `app/tests/unit/` (trasy API, akcje, serwer), `app/tests/e2e/` (przeglądarka), `ui/tests/`, `testkit/tests/` (narzędzia testowe i skrypty repozytorium: hooki agenta (`.claude/hooks/`), skaner sekretów, `check:context`, `release:version`, `release:notes`).

- **Migracje i współbieżność na PostgreSQL** (część `npm run test:db`, osobny serwer: `TEST_DATABASE_URL`): `packages/db/tests/migrations-roundtrip.integration.test.ts` (`up` -> zrzut schematu -> `down` każdej migracji poza bazową -> schemat równy zrzutowi po bazowej -> `up` -> schemat równy pierwszemu zrzutowi; pusta baza i baza z danymi demo; dla nowej migracji dowód i plan wycofania w opisie PR-a: `engineering-standards.md` §12) oraz `packages/db/tests/concurrency.integration.test.ts` (równoległe akceptacje zaproszenia, zaproszenia na ten sam adres, zmiany roli z tym samym `expectedVersion`, usuwanie ostatniego właściciela, potwierdzenie importu, decyzje o parach z `If-Match`, wydawanie i potwierdzanie kodów, limit kodów na sesję; ok. 4 s). Uruchomienie jednego pliku: `cd packages/db && TEST_DATABASE_URL=… npx vitest run --config vitest.integration.config.ts tests/<plik>`.

## Środowisko testowe

Jedna komenda stawia jednorazowe środowisko do testów ręcznych i agentowych (skill `om-prepare-test-env`, skrypty POSIX `sh`).

| Polecenie | Do czego |
|---|---|
| `npm run test-env:up` (`sh .ai/scripts/test-env-up.sh`) | stawia środowisko albo podłącza się do działającego; wypisuje `TEST_ENV_BASE_URL=…` i zapisuje deskryptor `.ai/qa/test-env.json` |
| `npm run test-env:down` (`sh .ai/scripts/test-env-down.sh`) | zatrzymuje dokładnie to, co uruchomił `up` (aplikację, kontener albo bazę); można uruchomić dwa razy |

- **Co powstaje:** świeża baza PostgreSQL z prawdziwymi migracjami, dane demo (`halka`) i druga restauracja `bistro-e2e` z polecenia operatora (jak w `packages/app/tests/e2e/global-setup.ts`), potem ZBUDOWANA aplikacja na wolnym porcie `127.0.0.1` z `DATA_SOURCE=postgres`, `AUTH_COOKIE_SECURE=false`, `ALLOW_DEMO_DATA=true`.
- **Baza:** gdy działa Docker, kontener `postgres:16` na losowym porcie (`wm-qa-pg-<runId>`); w przeciwnym razie nowa baza `winematch_qa_<runId>` na serwerze z `TEST_DATABASE_URL` (ta sama zmienna musi być ustawiona przy `down`, który usuwa tę bazę i nie rusza innych). Wynik mówi, którą drogą poszło: `TEST_ENV_DATABASE=docker|TEST_DATABASE_URL`.
- **Szybka ścieżka:** `npm run build` tylko gdy zmieniły się źródła (cache `.ai/qa/test-env-build-cache.json`, wymuszenie: `--force-rebuild`). Drugie `up` używa działającego środowiska (żywy proces, sondy HTTP, logowanie kontem demo, wiek ≤ `TEST_ENV_CACHE_TTL_SECONDS`, domyślnie 600 s, brak nowszych źródeł); `--force` stawia od nowa.
- **Dane logowania:** deskryptor wskazuje zmienne (`TEST_SOMMELIER_PASSWORD` …) w gitignorowanym `.ai/qa/test-env.env`; wartości to publiczne hasła demo, nie przepisuj ich do plików śledzonych.
- **Stan lokalny, poza gitem:** `.ai/qa/test-env.json`, `test-env.env`, `test-env-build-cache.json`, `test-env-app.log`, `test-env.lock/`.

## Narzędzia poza lockfile'em (CI)

Zależności projektu są w `package-lock.json` (sumy kontrolne); poniższe nie. Zmiana wersji = zmiana tego pliku i `.github/workflows/ci.yml`.

| Narzędzie | Gdzie | Przypięcie | Uwagi |
|---|---|---|---|
| npm | `npm install -g npm@11.20.0` w jobach z `npm ci` | dokładna wersja (zgodna z `packageManager` w `package.json`) | pobierane z rejestru npm przy każdym przebiegu; weryfikacja sumy przez rejestr, nie przez lockfile |
| `agent-browser` | job `e2e`, `AGENT_BROWSER_VERSION` | dokładna wersja 0.39.1, `--ignore-scripts` | binarki w paczce bez bitu wykonywalnego; skrypt poinstalacyjny pakietu tylko je `chmod`uje, pobiera brakującą binarkę i podmienia dowiązanie, więc krok CI robi `chmod +x` jawnie (opakowanie `bin/agent-browser.js` też poprawia bit przy starcie); deklaruje Node 24, działa na Node 22 (`--engine-strict=false`); sprawdzone tylko na macOS, job `e2e` obserwuj przy pierwszym przebiegu |
| przeglądarka i pakiety systemowe | `agent-browser install --with-deps` w jobie `e2e` | **nieprzypięte**: wersje z repozytoriów Ubuntu 24.04 i źródła przeglądarki z `agent-browser` 0.39.1 | znane ryzyko; ograniczone do jednorazowego runnera bez sekretów, tylko `contents: read` |
| akcje GitHub | `.github/workflows/*.yml` | pełny SHA commita, `# vX.Y.Z`; aktualizuje Dependabot | `actions/checkout`, `actions/setup-node`, `actions/upload-artifact`, `github/codeql-action` |
| obraz runnera | `ubuntu-24.04` (`codeql.yml`: `ubuntu-latest`) | etykieta, nie digest | zawartość obrazu zmienia GitHub |

**`ignore-scripts=true`** (`.npmrc`): skrypty cyklu życia zależności są wyłączone. Pakiety, które mają taki skrypt: `esbuild`, `protobufjs`, `ssh2`, `cpu-features`, `fsevents`; żaden nie jest potrzebny (uzasadnienie: `security-notes.md` §13). Gdy pakiet go wymaga: `npm rebuild <pakiet> --ignore-scripts=false` jawnie dla tego pakietu (sam `npm rebuild` respektuje `ignore-scripts`), nie wyłączenie flagi w `.npmrc`.
